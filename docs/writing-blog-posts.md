# Writing a blog post

Posts go up at [aisafetyuci.org/blog](https://aisafetyuci.org/blog). You write them in a web editor. No code needed.

## Before you start

You need a GitHub account with access to the `aisafetyuci/aisafetyuci` repository. Ask a current officer to add you if you don't have it.

## Write and publish

1. Go to [aisafetyuci.org/admin](https://aisafetyuci.org/admin) and click **Sign In with GitHub**. The first time, GitHub asks you to authorize "AISCI blog editor"; click **Authorize**.
2. Click **New** and fill in the form:
   - **Title**, **Date**, **Summary** (one or two sentences; it shows on the blog page and in link previews).
   - **Authors**: one name per line. Use the name exactly as it appears on the Team page, and the post will show that person's photo.
   - **Category**: Explainer, Research, Recap, Opinion, or Announcement.
   - **Cover image** (optional): landscape works best. If you add one, fill in **Cover image description** for people who can't see it.
   - **Feature at top of blog** (optional): puts the post in the large card at the top of /blog.
   - **Post**: the body. The toolbar handles headings, bold, links, images, and code.
3. Click **Save**. Your post is now a **draft**. Nothing is public on aisafetyuci.org yet.
4. **Preview it**: about 2 minutes after saving, a **View Preview** button appears at the top of the editor. It opens your post on a preview copy of the site, exactly as it will look. The preview isn't listed anywhere, but anyone you send the link to can open it. Save again after changes, and the preview updates about 2 minutes later. If the button still says **View on Live Site**, the preview isn't ready yet: wait a minute, reload the page, and open the post again.
5. When it's ready, set **Status** (top right) to **Ready**, then click **Publish**. The post appears on aisafetyuci.org/blog about 2 minutes later.

The **Editorial Workflow** page (third icon, top left) shows every draft as Drafts → In Review → Ready. Use **In Review** if you want someone else to read the post first.

## Editing or deleting a published post

- **Edit**: open the post, change it, and save. The edit is a new draft; publish it the same way. For a meaningful change, set **Last updated** to today.
- **Delete**: tick the post in the list and click **Delete**, then confirm it under **Pending Deletion** on the Editorial Workflow page.

## If something goes wrong

- **The post never appears after publishing**: the site checks every post before it goes live. If a check fails (for example, a cover image without a description), the live site keeps showing the last good version. Ask whoever maintains the site to look at the build.
- **Signed out**: logins last about 8 hours. Sign in again.
- **Anything else**: ask whoever maintains the site (see the repository README).
